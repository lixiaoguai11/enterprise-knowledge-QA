# 01 — 需求与成功标准

## 用户与目标

目标用户是需要查询企业制度或产品资料的员工。系统应以可核对的资料帮助员工作答，明确显示证据、资料缺口和任务状态。

## 范围

- 唯一用户入口为交互式命令行 REPL。
- 支持带当前会话上下文的多轮提问。
- 检索本地带文档 ID、版本日期的制度/产品资料，提供候选检索和原文读取工具。
- 模型可在检索、读原文、追问和结束之间动态决策。
- 返回回答、引用文档 ID 与原文、资料缺口、状态和工具 Trace。
- 不在本版本提供 Web、HTTP API、身份认证、文档上传 UI、请假审批等业务流程。

## 成功标准

1. 对有单一支持证据的问题，回答与引用原文一致。
2. 对 D01 的 30 天与 D02 的 15 天冲突，列明双方引用，指出无适用范围/优先级并追问；不擅自选值。
3. 对资料外问题明确拒答并说明资料缺口。
4. 改写后的相似问题能触发合适的检索。
5. 上下文追问能利用前轮问题和回答，但事实仍需知识库证据支持。
6. 检索/原文工具或模型调用失败时返回明确错误状态，不输出伪造的确定答案。
7. 替换资料后，答案、引用或冲突动作会按新证据变化。

## 不变量

- 用户可看到原文引用和来源版本日期。
- `answered` 必须至少有一条来自工具结果的精确引用。
- 同一事实存在无法由范围或优先级解释的冲突时，状态必须是 `needs_clarification`。
