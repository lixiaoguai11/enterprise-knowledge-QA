# 01 — 需求、范围与成功标准

## 为什么做这个项目

企业制度和产品知识分散在多份文档中。员工提问常用口语表达，也可能省略前文对象；同一主题还可能有不同版本。项目以可检索资料为回答依据，让员工同时看到答案、原文出处和任务状态。

交付目标是可运行、可审查的 CLI Agent：模型根据工具观察选择搜索、读原文、追问或结束；程序校验引用与状态，并为冲突资料保留判定缺口。

## 用户、场景和核心任务

| 项目 | 定义 |
|---|---|
| 主要用户 | 需要查找公司制度、流程或产品说明的员工 |
| 输入 | 当前自然语言问题；可选的本进程对话历史 |
| 知识材料 | 带文档 ID、更新时间、标题、来源和正文的 Markdown 文件 |
| 工具 | `search_documents` 搜索候选片段；`read_document` 按 ID 读取已导入原文切片 |
| 结果 | `answer`、`citations`、`gaps`、`status`、工具 Trace |
| 用户价值 | 快速知道“资料写了什么、来自哪份文档、还缺什么信息” |

## 需求如何变成系统行为

1. 用户可以用不同措辞问同一件事，因此检索要支持关键词和语义近似召回。
2. 检索片段只能用于定位证据；需要检查范围、例外或优先级时，Agent 应能读原文。
3. 程序检查 `doc_id` 与 `quote` 是否来自本轮工具输出；没有有效引用时，不返回 `answered`。
4. 同一问题得到相互矛盾的资料时，日期新旧本身不能代表范围与优先级；系统应列明冲突并询问，而非猜一个值。
5. 资料不足、工具或模型失败、执行上限分别使用明确状态，让员工知道应补资料、重试还是缩小问题。
6. 以可重复的脚本化测试覆盖动态路径，并把模拟结果与真实模型结果分开记录。
7. 保存至少两条真实模型运行路径，记录工具参数、返回摘要、后续动作及可观察的决策依据，展示模型如何随工具结果调整动作。
8. 限制每轮执行长度；达到模型步数或工具调用上限时返回明确的 `incomplete` 状态。

## 范围内

- 唯一用户入口是交互式 CLI REPL。
- 支持 `/help`、`/new`、`/exit`，支持本进程内多轮上下文。
- 支持 Markdown 导入、文档 ID/日期、检索片段和按 ID 读文档。
- 保留 BM25 基础检索，可启用向量召回、RRF 融合和可切换的候选重排（BGE embedding 相似度或兼容 rerank API）；重排 backend 通过统一接口扩展。
- DeepSeek 使用 OpenAI 兼容 Chat Completions 与 function calling；Anthropic 协议可选使用 Messages API 与工具调用。
- 展示回答、引用、资料缺口、状态和工具 Trace。
- 提供合成资料、自动化测试和示例运行记录。

## 本次交付范围之外

- Web 页面、HTTP API、登录/角色权限和请假审批。
- 文档上传管理 UI、企业目录服务、多人对话隔离、跨进程历史持久化。
- 生产级审计、敏感数据治理、密钥服务、SLA、多实例数据库和权限控制。
- 自动替业务部门裁定冲突制度、替代人工合规判断。
- 将脚本化测试结果作为真实模型质量结论。

## 验收矩阵

| 编号 | 输入类型 | 必须观察的行为 | 证据所在 |
|---|---|---|---|
| A1 明确答案 | 单一文档有相关事实 | 回答有依据；显示对应文档 ID、日期和原文 | `tests/test_qa_agent.py`、`examples/01-normal-context.json` |
| A2 文档冲突 | D01=30 天、D02=15 天，无范围/优先级 | 同时引用两方，标明缺少判定规则并追问；不能只答一方 | 冲突测试、`examples/02-conflict.json` |
| A3 资料外问题 | 知识库无相关资料 | `insufficient_evidence`，不以模型常识补答 | 缺口测试、`examples/03-gaps-and-failure.json` |
| A4 改写问题 | 口语化表达与文档措辞不同 | 模型可为搜索选择不同 query，仍引用正确来源 | 改写测试、`examples/01-normal-context.json` |
| A5 上下文追问 | 当前问题省略前轮对象 | 上下文传给模型，检索 query 能补全指代；事实仍需证据 | 上下文测试、`examples/01-normal-context.json` |
| A6 工具失败 | 检索或读取异常 | `tool_error`、Trace 记录失败、不给出基于不完整资料的确定答案 | 工具失败测试、`examples/03-gaps-and-failure.json` |
| A7 资料替换 | 将 D01 数字从 30 改为 20 | 新结果中的答案和原文引用跟着变化；冲突是否仍存在取决于 D02 | `mutation_check`，但当前仅验证 Agent 看到变化后的工具证据时会传播新证据 |
| A8 动态决策记录 | 不同问题/检索结果 | 真实模型依据观察结果继续搜索、读取原文或结束；Trace 记录动作和结果摘要 | `examples/05-live-anthropic-success.json`、`examples/08-live-qwen-reranker.json`、`examples/09-live-product-question.json` |
| A9 执行上限 | 模型持续请求工具或一条响应并行请求多个工具 | 6 轮模型请求或 8 次工具调用后停止，状态为 `incomplete` | `tests/test_qa_agent.py` 的轮数及工具次数上限测试 |

## 可检查的不变量

- 每个 citation 的 `doc_id` 来自本轮工具返回；`quote` 是对应工具原文 quote 的子串。
- `answered` 至少有一条通过来源检查的引用，否则降级为 `insufficient_evidence`。
- 已识别的相关数字冲突不能作为普通 `answered` 返回。
- 工具异常或模型调用异常返回 `tool_error`；达到决策上限返回 `incomplete`。
- 资料日期要跟随引用显示，但除非资料明确规定，否则不得把日期新旧直接用作优先级规则。

## 如何解读验收证据

脚本化测试验证给定输入下的控制流和状态；真实运行 Trace 记录当次模型和服务的实际动作。两类证据分别列在[评估文档](03-evaluation.md)，其中包括冲突澄清成功和结构化输出失败的真实运行记录。
