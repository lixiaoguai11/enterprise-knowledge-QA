# 04 — AI 辅助开发记录

## 使用边界

本项目在需求拆分、代码编写、文档整理和问题排查过程中使用了 Codex（AI 编程助手）。AI 参与的是开发协作，不是运行时 Agent 的替代说明。评审时应把“AI 写出的实现”“开发者作出的选择”和“由测试或真实运行验证的行为”分开看。

## AI 参与了什么

| 工作 | AI 辅助内容 | 开发者提供或确认的输入 | 如何验证/复核 |
|---|---|---|---|
| CLI-only 改造和 Agent 主链路 | 梳理旧项目范围，协助实现 CLI、工具调用循环、引用校验和冲突守卫 | 明确要求只有 CLI、制度与产品问答、冲突时不自行择一 | 阅读 `backend/app/cli.py`、`qa_agent.py`、`knowledge_tools.py`；pytest 和离线 Trace |
| 模型与检索接入 | 协助实现 Embedding、Reranker provider 抽象、Qwen rerank 请求适配及 DeepSeek/Anthropic 协议切换 | 提供实际服务配置格式，并澄清 `16386` 是远端 `192.168.110.23` 的端口 | `tests/test_reranker.py` 的隔离协议测试；2026-10-30 真实 Embedding、Qwen rerank 和模型请求 Trace |
| 运行证据和评估 | 协助编写离线 smoke、真实在线 smoke、测试及 Trace 说明 | 授权使用配置的 API 做在线验证，并指出初次把服务器端口误当 localhost 的错误 | 对照原始 JSON Trace、状态断言和测试退出码；失败运行也保留，不只记录成功结果 |
| 学习型文档 | 协助整理需求、调用顺序、设计取舍、局限和从零上手说明 | 要求以从 0 到 1 的开发者视角写清决策及考虑点 | 文档中的行为描述与当前源码、示例和运行结果交叉检查 |

## 开发者作出的关键选择

- 采用 CLI REPL 作为唯一入口，先完成最小可运行问答闭环。
- 不引入 Agent 框架：当前只有两个只读工具和有限循环，保留 SDK 工具调用接口可以直接检查每次模型消息和工具结果。
- 使用合成 FAQ/制度完成演示，不把示例中的制度描述成真实企业政策。
- 把冲突检测作为一层保守保护：数字、单位和句式相同的明确冲突可由代码覆盖模型答案；更广泛的语义矛盾仍依赖模型和人工评估。
- 隔离测试使用替身以便重复运行；真实 API 运行另存 Trace，不能用 Mock 结果证明真实模型决策质量。
- 对无效模型结构化输出选择 `tool_error` 安全失败，不尝试猜测或从自由文本拼装一个答案。

这些选择的实现依据、代价和后续改变条件见 [02-solution.md](02-solution.md) 与 [05-retrospective.md](05-retrospective.md)。

## 个人复核与修改

开发者检查了 AI 生成的实现是否遵守用户指定的远端 rerank 地址，纠正了将 `192.168.110.23:16386` 写作 localhost 的配置误解；在考核标准补充后，又要求并核对模型实际工具动作、工具返回摘要、执行上限和真实运行证据。代码不是仅凭生成结果接受：当前 pytest 为 16 项通过，离线脚本 6 个场景通过；真实在线模型曾有成功冲突运行，也出现过最终 JSON 无法解析的 `tool_error`，两者均按实际 Trace 记录。

项目累计开发总时长没有从第一天开始计时，无法可靠还原。2026-10-30 本轮考核要求审计、决策 Trace 和文档补齐用时按本次工作记录，分钟级估计约 6 分钟；不要把该数误读为整个项目用时。

## 隐私和提交

- 未把 `.env`、API Key 或完整密钥值写入仓库 Trace。
- Trace 保存模型/provider 名、查询参数、文档 ID 和合成资料片段；真实数据接入前，应再次审核脱敏范围。
- AI 生成或改写的代码与文档均属于本仓库交付内容，最终责任仍由开发者复核；模型运行记录只证明当次观察到的结果。
