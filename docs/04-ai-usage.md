# 04 — AI 辅助开发记录

## 使用边界

本项目在需求拆分、代码编写、文档整理和问题排查过程中使用了 Codex（AI 编程助手）。AI 参与的是开发协作，不是运行时 Agent 的替代说明。评审时应把“AI 写出的实现”“开发者作出的选择”和“由测试或真实运行验证的行为”分开看。

## AI 参与了什么

| 工作 | AI 辅助内容 | 开发者提供或确认的输入 | 如何验证/复核 |
|---|---|---|---|
| CLI-only 改造和 Agent 主链路 | 梳理旧项目范围，协助实现 CLI、工具调用循环、引用校验和冲突守卫 | 明确要求只有 CLI、制度与产品问答、冲突时不自行择一 | 阅读 `backend/app/cli.py`、`qa_agent.py`、`knowledge_tools.py`；pytest 和离线 Trace |
| 模型与检索接入 | 协助实现 Embedding、Reranker provider 抽象、Qwen rerank 请求适配及 DeepSeek/Anthropic 协议切换 | 提供实际服务配置格式，并澄清 `16386` 是远端 `192.168.110.23` 的端口 | `tests/test_reranker.py` 的隔离协议测试；2026-10-30 真实 Embedding、Qwen rerank 和模型请求 Trace |
| 运行证据和评估 | 协助编写离线 smoke、真实在线 smoke、测试及 Trace 说明 | 授权使用配置的 API 做在线验证，并指出初次把服务器端口误当 localhost 的错误 | 对照原始 JSON Trace、状态断言和测试退出码；失败运行也保留，不只记录成功结果 |
| 学习型文档 | 协助整理需求、调用顺序、设计取舍、局限和从零上手说明 | 要求以从 0 到 1 的开发者视角写清决策及考虑点 | 文档中的行为描述与当前源码、示例和运行结果交叉检查 |

## 项目设计与技术栈的决策归属

本项目的业务范围、CLI-only 入口、Python 技术栈、检索与重排方案、模型协议选择、工具边界、测试策略以及各层安全约束，均由项目开发者（用户）提出并选型。AI 没有替开发者决定整体架构或技术路线；AI 的工作是依据这些选择协助编码、补充实现细节、解释取舍、整理文档和执行验证。

下列决策是开发者确定的方向，表中理由用于解释和复核开发者的方案，不应被理解为 AI 替开发者作出的选择：

- 采用 CLI REPL 作为唯一入口，先交付最小可运行问答闭环。
- 使用 Python，并选择原生 SDK 工具调用循环，不引入 Agent 框架。
- 使用合成 FAQ/制度完成演示，不把示例资料描述成真实企业政策。
- 使用 BM25、向量检索、RRF 与可切换 reranker；接入 DeepSeek/Anthropic-compatible 模型协议。
- 对明确数字冲突加程序保护；更广泛语义冲突需模型与人工评估。
- 用脚本替身做可重复的隔离测试，同时用真实 API Trace 验证在线链路；两类证据分开解释。
- 对模型结构化输出无效选择 `tool_error`，不猜答案、不从自由文本拼装答案。

这些方案的工程实现、设计理由、代价和可能的后续改变条件见 [02-solution.md](02-solution.md) 与 [05-retrospective.md](05-retrospective.md)。文档整理决策理由是为了让评审理解开发者的思路，并不改变上述决策归属。

## 个人复核与修改

开发者提供并决定了整体技术栈与全部设计方向，也提供模型、Embedding 和 rerank 服务的调用配置，澄清 `16386` 是远端 `192.168.110.23` 的端口。AI 曾将它误写作 localhost，开发者指出后已纠正。考核标准补充后，开发者要求并核对模型实际工具动作、工具返回摘要、执行上限和真实运行证据。代码不是仅凭生成结果接受：当前 pytest 为 16 项通过，离线脚本 6 个场景通过；真实在线模型曾有成功冲突运行，也出现过最终 JSON 无法解析的 `tool_error`，两者均按实际 Trace 记录。

项目累计开发总时长没有从第一天开始计时，无法可靠还原。2026-10-30 本轮考核要求审计、决策 Trace 和文档补齐用时按本次工作记录，分钟级估计约 7 分钟；不要把该数误读为整个项目用时。

## 隐私和提交

- 未把 `.env`、API Key 或完整密钥值写入仓库 Trace。
- Trace 保存模型/provider 名、查询参数、文档 ID 和合成资料片段；真实数据接入前，应再次审核脱敏范围。
- AI 生成或改写的代码与文档均属于本仓库交付内容，最终责任仍由开发者复核；模型运行记录只证明当次观察到的结果。
